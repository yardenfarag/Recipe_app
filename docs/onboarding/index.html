Pinch developer guide

This page explains how Pinch is built and how we work on it. It was written for a developer joining the project. It is a reference, not a tutorial: skim it once, then come back to the section you need.

What Pinch isA mobile and web app. You give it a cooking video link (TikTok, Instagram, YouTube), a recipe web page, or a photo of a recipe card. It returns a structured recipe (ingredients, steps, servings, time) and saves it to your library. You can then scale servings, swap ingredients, translate, build a shopping list, and cook along with the video.
AppExpo SDK 54 (React Native), Expo Router, NativeWind (Tailwind), i18next. One codebase for iOS, Android, web.
BackendSupabase: Postgres with Row Level Security, Auth, Storage, and 11 Edge Functions written in TypeScript for Deno.
AIEvery model call goes through OpenRouter, one model per task: GPT-6 Luna for text, Claude Sonnet 5.5 for photos, GPT-6.1 Sol for translation, Gemini 3.5 Flash for video, Jev for the gates. See section 6.
Websitepinch-app.io on GitHub Pages (static landing page plus the web app under /app), with a Cloudflare worker for shared-recipe pages.
Work trackingLinear workspace pinch-recipe, team key PIN. GitHub PRs into master. EAS for store builds.
Repogithub.com/yardenfarag/Recipe_app (public)

Money model

  • No subscription.
  • Every signed-in user gets 10 free extract credits per calendar month (UTC).
  • More credits are bought as one-time packs: 10, 30 or 100. Purchased credits never expire.
  • Purchases go through RevenueCat. They are switched off right now (EXPO_PUBLIC_CREDIT_PURCHASES_ENABLED=false).

2 · System overview

What talks to what

app callsinside Supabaseoutside services (paid APIs; keys are Supabase secrets)dashed = indirect

Three rules

1. App ↔ database directlyFor normal data (recipes, lists, collections) the app uses the Supabase JS client. Row Level Security makes this safe: every policy checks user_id = auth.uid().
2. Secrets and money go through Edge FunctionsAI calls, scraping, credits, account deletion. The app only holds the Supabase URL and the publishable key.
3. Edge Functions do not save recipesThey return JSON. The app shows a preview and the user saves. "Extracted" and "saved" are two different events.

Example: one Snap, end to end

  1. User pastes https://www.instagram.com/reel/ABC123/ and taps "Fork it!".
  2. App calls supabase.functions.invoke('extract-recipe', { body: { url, request_id } }) (src/lib/supabase/extractRecipe.ts).
  3. The function checks the user's library and the Hub. Miss. It fetches the post from ScrapeCreators, runs the gates, reserves 1 credit, calls the model, classifies the result.
  4. Response: { status: 'full', platform: 'instagram', recipe: {...}, tokens_charged: 1, total_credits: 2 }.
  5. App stores the recipe as a draft in AsyncStorage and opens /recipe/preview.
  6. User taps Save. App inserts into recipes through RLS (src/lib/supabase/recipes.ts).

How state and data work

SessionStored in AsyncStorage by the Supabase client. useAuth() gives you user and loading.
Sign-in requireduseOnboardingGate sends new installs to /onboarding and signed-out users to /auth. Old docs describe a guest mode; it is switched off.

Snap callOne blocking functions.invoke. The app sends a request_id (one per URL, kept in AsyncStorage) so a retry cannot be charged twice. The rotating status text while waiting is a 2.8 s timer, not progress from the server.

Analyticssrc/lib/analytics.ts inserts rows into product_events. Events: recipe_extracted, recipe_saved, paywall_viewed, onboarding_completed, app_shared. No third-party SDK.

4 · Backend

Edge Functions

Edge Functions are small TypeScript HTTP handlers that Supabase runs on Deno. They hold the API keys, do the AI work and manage credits. Each one has a matching client file in src/lib/supabase/. All of them are POST with JSON bodies. All verify the user's JWT except the RevenueCat webhook.

5 · Database

Postgres with Row Level Security

  • One Supabase project: recipe_app, ref ccobefeofhnncpgifxel, region eu-central-1, Postgres 17.
  • Migrations live in supabase/migrations/. Never edit an old one. 0001 to 0043 are numbered; every new one gets a UTC timestamp from npx supabase migration new <name> (e.g. 20261022150000_recipe_appliances.sql), so two branches can't claim the same number. scripts/migrations.test.mjs fails CI on a new 4-digit number or a duplicate version.

6 · AI pipeline and models

What runs when you Snap, and which model answers

The extract-recipe pipeline

  1. Detect the platformyoutube, instagram, tiktok, web, or photo. Anything else returns coming_soon. File: _shared/platform.ts.
  2. Library cacheUser already saved this URL? Return it.
    free · cached: true
  3. Hub cacheAnother user extracted this URL and allowed Hub publishing? Return that card.
    free · from_hub: trueskipped when force_extract is set
  4. Require sign-inNo session → 401 auth_required.
  5. Fetch the postYouTube: description, top 10 comments (creator first), captions, duration. Instagram and TikTok: ScrapeCreators. Web: the page, preferring schema.org JSON-LD.
    limits: 10,000 chars description · 6,000 chars captions · 12 comments
  6. Two gates, in parallel with an early text extraction
    Jev extract gateAsks Jev to choose one of full_recipe_in_text, partial, needs_video, no_recipe from the text. About 0.3 s. Only trusted above 0.75 confidence. On error or low confidence, the normal ladder runs. PIN-46.
    Content gate"Is this food?" unrelated → not_food, no credit. A plated dish, or a video over 3 minutes with no text → looks_like_dish with a dish_guess, so the app can offer "Guess the recipe" or "Extract anyway".
    not_food · no creditlooks_like_dish · no creditneeds_video → skip the text call
  7. Reserve one creditreserve_recipe_credit with the app's request_id. Not enough credits → 402 insufficient_credits, app shows the paywall.
    1 credit held
  8. Content ladder, cheapest first
    Rung 1: textOne call with all text sources together. If the result is full (title, ingredients and steps), stop here. If partial, keep it and continue.
    Rung 2: videoOnly if there is a video shorter than 3 minutes. The clip is downloaded in the function and sent inline (20 MB cap). If Instagram's CDN refuses, a ScrapeCreators-hosted copy is fetched instead. The model gets the video plus all the text.
    WinnerThe more complete result. Score: title 1, ingredients 2, steps 2.
    PhotosSkip the ladder. One vision call.
    file: _shared/gemini.ts → extractRecipeWithLaddervideo over 180 s → video_too_long
  9. Classifyfull, partial (with missing_fields), or failed.
    full or partial → finalize creditfailed → refund
  10. ReturnRe-host the thumbnail in Storage, publish a full result to the Hub unless the user opted out, log usage to ai_usage_events, return JSON. The app opens Preview. Saving is the app's job.

How a model gets picked

  • Every AI call goes through generateLlmJson() in supabase/functions/_shared/llmClient.ts.
  • Each call has a kind. TASK_MODELS[kind] gives the primary model, the fallback list (sent as models[], OpenRouter tries them in order) and the reasoning effort.
  • Override per task with Supabase secrets: OPENROUTER_MODEL_<KIND>, OPENROUTER_FALLBACKS_<KIND>, OPENROUTER_REASONING_<KIND>.
  • Every request sets require_parameters: true (skip hosts that ignore the JSON schema) and, for Anthropic models, ignore: ['azure'] (Azure's filter truncates the JSON).
  • Video also goes through OpenRouter. YouTube links are passed as a URL; other clips are sent inline as base64, because OpenRouter does not fetch arbitrary MP4 URLs.
  • The Jev gate uses OpenRouter's decisions endpoint, not chat completions. It has no fallback; on error the normal ladder runs.

Things to know when you change a model

  • Change the default in TASK_MODELS, or set an OPENROUTER_MODEL_<KIND> secret for a quick production experiment.
  • Sonnet 5.5 and GPT-6.1 Sol reject reasoning: none with 400 Reasoning is mandatory. Give them low.
  • Qwen often wraps the JSON in an array; the router unwraps a top-level array when the schema wants an object.
  • Cost per call comes from OpenRouter's usage.cost and lands in ai_usage_events.gemini_cost_usd (column name is historical). The rate table in pricing.ts is only a fallback.
  • Run the router tests, then redeploy all seven model-calling functions together (supabase/README.md, "Per-task models").
  • Rerun the eval when a default changes and keep eval/models.ts in step.
Known pitfall. OpenRouter rejects the whole request if any slug in models[] has been retired. A retired google/gemini-2.0-flash slug silently pushed every fast call to the Gemini fallback for weeks (fixed in commit 5ed0b00). If you change a model list, check the slug at openrouter.ai/api/v1/models.

The eval harness (eval/)

  • Re-runs the production task functions with one pinned model and no fallbacks, then grades with a judge model.
  • Use it before changing a prompt or a default model. Results go in eval/results/summary.md.
  • Needs OPENROUTER_API_KEY and SCRAPECREATORS_API_KEY in .env. A full run cost about $7.
npx -y deno run -A --no-lock --env-file=.env eval/cli.ts run --task=text --models=openai/gpt-6-luna --limit=3
npx -y deno run -A --no-lock --env-file=.env eval/cli.ts judge
npx -y deno run -A --no-lock --env-file=.env eval/cli.ts report

10 · Agent skills

How we work with the agent

Most Pinch work is done with an AI agent (Claude Code or Cursor). We drive it with Matt Pocock's skills: short, slash-command playbooks like /grill-with-docs or /tdd. Install them before you take your first ticket.

Why this matters

The agent builds the wrong thingUsually it misunderstood the ticket. /grill-with-docs makes it interview you before it writes code, so the gaps show up in conversation instead of in review.
It forgets between sessionsThe grilling writes what it learns to CONTEXT.md (our shared words: Snap, credit, gate, ladder) and to ADRs in docs/adr/. The next session, and the next person, start from that.
The code doesn't work/tdd and /implement work red, green, refactor, one slice at a time, and end with /code-review against our standards and the ticket.
Work is too big for one session/wayfinder and /to-tickets split it into tickets small enough for one fresh session each, with blocking links in Linear.
Two people, one way of workingWhen we both use the same skills, tickets, specs and PRs look the same, and either of us can pick up the other's work. The Approach label on every ticket only works if you have the skills.
